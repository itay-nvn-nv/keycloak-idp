# Standalone Keycloak

Isolated Keycloak on an empty Kubernetes cluster. It can run forever as its own IDP. Attaching a Run:AI control plane is a separate, optional step.

This path does **not** modify the bundled `runai-backend` install. It reuses the shared [`../realm.json`](../realm.json) and the existing realm-import / Run:AI scripts from [`../runai-backend/scripts/`](../runai-backend/scripts/).

`deploy.sh` installs the **Bitnami Keycloak Helm chart** (PostgreSQL is a subchart of that release). Keycloak does not publish its own Helm chart; this is the packaged chart that ships a database.

## What you get

1. **`deploy.sh`** — Helm release `keycloak` (Keycloak + Postgres + Ingress or LoadBalancer), admin secret, and a `mock-idp` realm imported with placeholder control-plane URLs.
2. **`integrate.sh`** *(optional)* — given a Run:AI control plane URL, rewrite Keycloak clients, create the IDP connector, sample project `dev-team`, and the developer-group access rule.

Placeholder URLs are required at deploy time: Keycloak rejects non-absolute redirect URIs, and the real control plane URL / IDP alias are not known yet. `realm.json` already uses:

```
RUNAI_CTRL_PLANE_URL_PLACEHOLDER/auth/realms/runai/broker/RUNAI_IDP_ALIAS_PLACEHOLDER/endpoint
```

Deploy substitutes the control-plane host with `https://runai-ctrl-plane.placeholder.invalid`. Integrate replaces that with the real URL, then the existing `03-runai-setup.sh` fills in the alias the control plane generates.

## Prerequisites

- `kubectl` pointed at the **Keycloak** cluster
- `helm` 3
- `jq`
- An Ingress controller (default) **or** a cloud LoadBalancer
- A StorageClass for Postgres (persistence is disabled if none exists)
- Outbound access from that cluster to the Run:AI control plane **only when you run integrate**
- The Run:AI control plane must be able to reach the Keycloak public URL (OIDC discovery / SAML metadata)

## 1) Deploy Keycloak

```bash
./standalone/deploy.sh
```

You will be asked for a hostname (for example `keycloak.example.com`). DNS or `/etc/hosts` must resolve it to the Ingress / LoadBalancer.

Non-interactive example:

```bash
KEYCLOAK_HOSTNAME=keycloak.example.com \
KEYCLOAK_TLS_SECRET=my-tls \
INGRESS_CLASS=nginx \
./standalone/deploy.sh
```

Useful environment variables:

| Variable | Meaning |
|--|--|
| `KEYCLOAK_HOSTNAME` | Public hostname (required in non-interactive mode) |
| `KEYCLOAK_NAMESPACE` | Namespace (default `keycloak`) |
| `KEYCLOAK_ADMIN` | Admin username (default `admin`) |
| `KEYCLOAK_ADMIN_PASSWORD` | Admin password (default `admin`) |
| `KEYCLOAK_TLS_SECRET` | Existing `kubernetes.io/tls` secret |
| `KEYCLOAK_TLS_SECRET_NAMESPACE` | Copy that secret from another namespace |
| `KEYCLOAK_TLS_MODE` | `existing`, `selfsigned`, or `none` |
| `KEYCLOAK_SKIP_TLS` | Set to skip TLS (HTTP) |
| `EXPOSE_MODE` | `ingress` (default) or `loadbalancer` |
| `INGRESS_CLASS` | IngressClass name |
| `KEYCLOAK_STORAGE_CLASS` | Postgres PVC class |
| `KEYCLOAK_USE_EMPTYDIR` | Disable Postgres PVC |
| `KEYCLOAK_CHART` | Chart ref (default `oci://registry-1.docker.io/bitnamicharts/keycloak`) |
| `KEYCLOAK_CHART_VERSION` | Chart version (default `25.2.0`) |
| `KEYCLOAK_HELM_RELEASE` | Helm release name (default `keycloak`) |
| `BITNAMI_KEYCLOAK_IMAGE` | Image repo (default `bitnamilegacy/keycloak`) |
| `BITNAMI_POSTGRES_IMAGE` | Image repo (default `bitnamilegacy/postgresql`) |
| `KEYCLOAK_FORCE` | Recreate jobs / skip prompts where applicable |

Images default to `bitnamilegacy/*` because Bitnami's public versioned tags are no longer pullable without a subscription. `global.security.allowInsecureImages` is set so the chart accepts that override.

TLS:

- Prefer a real certificate the remote Run:AI control plane will trust.
- Self-signed is generated by the Helm chart (`ingress.selfSigned`). OIDC/SAML from Run:AI will fail until that CA is trusted on the control plane.
- LoadBalancer mode is HTTP only (no Ingress terminator).

When it finishes, Keycloak is up with users/groups/clients and **no** Run:AI connection. Admin console: `https://<hostname>/admin/` (`admin` / `admin`).

## 2) Optional: integrate a remote Run:AI control plane

Run this against the **same kube context** as deploy (so the script can read the Keycloak admin secret). Integration runs **on this machine** by default, because it must reach both the Keycloak URL and the Run:AI control plane. Kind / env-in-a-click clusters often cannot open TCP to a different Run:AI ELB.

```bash
./standalone/integrate.sh
```

Non-interactive:

```bash
RUNAI_CTRL_PLANE_URL=https://runai.example.com \
RUNAI_IDP_TYPE=OIDC \
./standalone/integrate.sh
```

Control-plane login defaults to `test@run.ai` / `Abcd!234` (override with `RUNAI_ADMIN_USERNAME` / `RUNAI_ADMIN_PASSWORD`). `RUNAI_IDP_TYPE` is `OIDC` or `SAML`.

To run the old in-cluster Job instead (only if that cluster can egress to the control plane):

```bash
INTEGRATE_MODE=in-cluster ./standalone/integrate.sh
```

The job:

1. Checks Keycloak and Run:AI are reachable
2. Rebuilds realm client JSON with the real control plane URL (reuses `02-keycloak-setup.sh`; import is skipped if the realm exists)
3. Patches live OIDC/SAML clients (entity ID, web origins, logout URLs)
4. Reuses `03-runai-setup.sh` to create the IDP, rewrite the broker redirect URI with the generated alias, and create project `dev-team` + the developer-group rule

That last step is the same logic as the bundled install, including the IDP-alias placeholder described in [`../runai-backend/README.md`](../runai-backend/README.md).

## Cleanup

Remove Run:AI objects only (Keycloak stays):

```bash
./standalone/cleanup.sh --integration-only
```

Destroy the Helm release and namespace (and Run:AI objects if integrated):

```bash
./standalone/cleanup.sh
```

Type `yes` to confirm, or set `KEYCLOAK_FORCE=1`.

## Layout

```
standalone/
  deploy.sh           # helm upgrade --install + realm import job
  integrate.sh
  cleanup.sh
  manifests/          # realm-import / integrate Jobs only
  scripts/            # Keycloak-only health check, client patch, TLS curl wrapper
```

Shared with option 1:

- `../realm.json`
- `../runai-backend/scripts/02-keycloak-setup.sh`
- `../runai-backend/scripts/03-runai-setup.sh`
- `../runai-backend/scripts/01-url-health-check.sh` (used by integrate, which must check both sides)
